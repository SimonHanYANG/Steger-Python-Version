# 缩小高斯导数周围计算范围测试

2026-11-06，分支 `experiment/gaussian-support-20261106`。
直接从最新发行版 `v1.0.2`（`f2e3081`）开始；`main` 和
`experiment/mask-only-20261106` 保持原样。

## 改了什么

计算一个位置的高斯导数时，离它很远的像素权重很小。因此可以试着缩短周围范围，
减少每次卷积要做的乘加运算；被省掉的权重虽小，却不是零，所以结果可能变化。

本次只新增 `gaussian_truncate` 参数，控制周围范围。整张ROI仍参加导数计算，
mask仍负责筛选颈部；平滑强度、五个进程、找线规则、异常末端处理和测角规则都保持发行版设置。
五个进程分别对同一张ROI尝试不同平滑强度，收集中心线后再统一选线、测角。
没有引入mask-only的计算方法。

默认 `gaussian_truncate=6.0`，与发行版输出一致。
半径为 `max(2, ceil(gaussian_truncate * sigma + 0.5))`，宽度为 `2 * 半径 + 1`。
下文用 `sigma=2` 时的范围命名档位；每张图实际核宽随它选中的 `sigma` 变化。
各档都缩短所有候选平滑强度的范围，没有删除任何平滑强度、明暗方向或补试步骤。
保留原有float64运算、核边缘尾部权重处理和三次插值。

“完整耗时”从内存里的ROI和mask传入开始，包含预处理、所有找线、必要的补试、
进程通信、最终选线和测角；不含读图、分割、绘图、进程启动或软件排队。
分割线程同时运行造成的CPU争用需要在实际软件里另测。
“仅导数”是另行固定 `sigma=2` 的独立计时，每档1160次，不能当作完整流程耗时。
完整P95依次为10.008、9.720、9.378、9.344、9.361、9.274、9.223 ms。

角度变化是与发行版的差，不是相对人工真值的误差。
位置差采用两条中心线之间双向点到线段距离的最大值，按约0.25像素弧长采样，
包含中心线端点范围的变化。

- 各档都为26张有最终角度、3张没有；不能仅凭返回数量相同判断精度不变。
- 23、19、17档的选中参数、点数、状态在本批保持一致，但坐标、法向或响应均已有数值差异。
- 15档有1张点数变化；13档有4张点数变化、1张选中参数变化；11档分别为10张和6张。
- 没有任何缩小档位达到29张中心线/法向/响应逐位一致；基准档29张一致。
- 19档最大角差约0.0013°，但有2张因恰好位于四舍五入边界，保留两位小数的显示值也发生变化。

**建议：19×19档可以作为后续小误差实验候选，不能宣称精度完全不变。**
它只节省约0.146 ms；导数只是总流程的一部分，范围缩小不会让完整耗时同比例减少。
本次所有档位的完整平均耗时仍高于5 ms。默认继续使用原范围；没有自动改为19档。

## 精度与一致性检查

- 全部225项回归测试通过，包括不同参数交替调用、并发调用隔离和异常恢复。
- 默认档18组导数数据与发行版逐位一致；全部29张真实图的完整结果、中心线及法向与已接受结果一致。
- 所有计时调用的结果都与对应参数的串行计算一致。
- 各档均通过原有84组合成定位/线宽/拟合通过率门槛，以及圆弧验收。
- 额外60条带噪声和像素取整的直线，关闭线宽及截面额外校正，使用颈部找线设置；各档均能测角。
  19档相对基准的最大角差约0.0000031°、定位P95最大变化约0.00000037像素。

通过合成验收表示仍在既定门槛内，并不表示所有输出相同。
真实精子没有人工角度真值，不能据此证明所有实际图像的精度都不变。

## 使用

以下代码放进软件现有的 `if __name__ == '__main__':` 启动流程内，
创建一次、持续复用；Windows启动子进程需要该入口保护。

```python
from steger.worker import NeckAngleWorker

with NeckAngleWorker(workers=5, gaussian_truncate=4.0) as worker:
    result = worker.measure(roi, neck_mask)  # σ=2时19×19
    baseline = worker.measure(roi, neck_mask, gaussian_truncate=6.0)
```

也可以调用 `measure_neck(roi, neck_mask, gaussian_truncate=4.0)` 进行串行计算。
`lines_gauss` 同样接受该关键字参数。忽略参数时仍为原版6.0。
